    11→## 1. EXECUTIVE SUMMARY
    12→
    13→### 1.1 Problem Statement
    14→
    15→Сервисы экипажей (VIP BIKE, NNVolt, и др.) нуждаются в унифицированной системе учета:
    16→
    17→- **Доходы:** аренда байков, продажа услуг сервиса, аренда оборудования (шлемы)
    18→- **Расходы:** зарплата сотрудников (механики, менеджеры), переводы из кассы
    19→- **Зарплата:** расчет ЗП с бонусами от аренды/продаж/услуг сервиса с выплатами 10 и 25 числа
    20→- **Ежедневная отчетность:** для ассистента и владельца экипажа
    21→- **Оборудование:** учет выдачи шлемов и экипировки (требуется новая таблица `equipment_rentals`, т.к. `rental_handoffs` не существует)
    22→
    23→### 1.2 Current Architecture Analysis
    24→
    25→#### ✅ Existing Tables (from `supabase.txt` snapshot 2026-07-23):
    26→
    27→**Public Schema:**
    28→```sql
    29→-- Crews & Members
    30→public.crews                    -- id, slug, name, owner_id, theme
    31→public.crew_members             -- id, crew_id, user_id, role (owner|co_owner|admin|mechanic|member)
    32→public.users                    -- user_id, username, full_name, metadata->role
    33→
    34→-- Catalog & Rentals
    35→public.cars                     -- id, make, model, type ('bike'|'accessories'), specs->sale_price, specs->rent_weekday_hour
    36→public.rentals                  -- rental_id, crew_id, vehicle_id, user_id, status, total_cost, metadata->service_description
    37→
    38→-- Private Schema (PII & Contracts)
    39→private.user_rental_secrets     -- chat_id, crew_slug, passport data, STS pledge
    40→private.rental_contract_artifacts -- contract_key, rental_id, crew_slug, PDF storage_path
    41→private.sale_contract_artifacts   -- contract_key, buyer_*, sale_price, warranty_months, crew_slug
    42→```
    43→
    44→#### ❌ Identified Gaps:
    45→
    46→1. **NO `service_operations` table** — услуги сервиса (сборка, настройка, ремонт) хранятся только в `rentals.metadata->service_description` без структуризации
    47→2. **NO `equipment_rentals` table** — шлемы и оборудование не имеют отдельного финансового учета аренды
    48→3. **NO `cash_transactions` ledger** — доходы/расходы разрознены по таблицам, нет единого cash flow
    49→4. **NO `commission_rates` configuration** — ставки комиссий менеджерам не настраиваются гибко
    50→5. **NO `salary_plans` with payout schedule** — нет плана ЗП с привязкой к 10 и 25 числам
    51→6. **NO `rental_handoffs` table** — выдача/возврат оборудования (шлемов) не отслеживается явно в БД
    52→7. **NO `document_drafts` table** — состояние черновиков документов не сохраняется между сессиями
    53→
    54→#### ⚠️ Important Findings from Deep Investigation:
    55→
    56→- **`rental_handoffs` does NOT exist** in current schema (supabase.txt 2026-07-23) — выдача шлемов НЕ отслеживается на уровне БД
    57→  - **Solution:** Create `public.equipment_rentals` table as single source of truth for equipment tracking
    58→  - No need to create `rental_handoffs` — equipment rentals table is cleaner approach
    59→  
    60→- **`crew_member_shifts` FULLY EXISTS AND WORKS** ✅
    61→  - Table structure confirmed: id, member_id, crew_id, clock_in_time, clock_out_time, duration_minutes (generated), hourly_rate, salary_amount, checkpoint (jsonb), actions (jsonb)
    62→  - Trigger `trg_calc_shift_salary` auto-calculates salary on clock_out (BEFORE INSERT OR UPDATE OF clock_out_time)
    63→  - Migration file: `app/wb/sql/shift_checkpoint.sql` adds checkpoint/actions JSONB columns
    64→  - Bot command `/shift` implemented in `app/webhook-handlers/commands/shift.ts`
    65→  - API endpoint `/api/crew/shifts` for CRUD operations (POST start, DELETE end, GET active)
    66→  - **Integration:** Use existing `crew_member_shifts` table for base salary calculation in `salary_plans` via foreign key relationship
    67→  
    68→- **`document_drafts` does NOT exist** — doc-manual.ts state persistence needs new table (PRD #2 proposes this)
    69→
    70→- **"vip-bike" is a crew slug** — NEVER hardcoded; all paths use `[slug]` parameter ✅
    71→
    72→- **Existing sales-analytics** (`app/franchize/[slug]/sales-analytics/SalesAnalyticsClient.tsx`) shows `SaleDashboardItem` without delivery method field — needs update
    73→

   107→### 2.2 Table: `public.service_operations`
   108→
   109→**Purpose:** Учет операций сервиса для любого экипажа
   110→
   111→```sql
   112→-- Migration: 20260809000001_create_service_operations.sql
   113→
   114→CREATE TABLE public.service_operations (
   115→  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
   116→  crew_id UUID NOT NULL REFERENCES public.crews(id) ON DELETE CASCADE,
   117→  
   118→  -- Operation details
   119→  operation_type TEXT NOT NULL CHECK (operation_type IN (
   120→    'assembly',      -- Сборка (например Folkon GT)
   121→    'tuning',        -- Настройка (ослабление цепи, регулировка)
   122→    'repair',        -- Ремонт
   123→    'maintenance',   -- ТО
   124→    'installation',  -- Установка (колеса, суппорты)
   125→    'removal',       -- Снятие
   126→    'inspection'     -- Диагностика
   127→  )),
   128→  
   129→  -- Link to bike/equipment
   130→  vehicle_id TEXT REFERENCES public.cars(id),
   131→  equipment_ids TEXT[],  -- Array of equipment IDs (helmets, wheels)
   132→  
   133→  -- Link to rental (if service is part of rental)
   134→  rental_id UUID REFERENCES public.rentals(rental_id) ON DELETE SET NULL,
   135→  
   136→  -- Financials
   137→  customer_price NUMERIC NOT NULL CHECK (customer_price > 0),
   138→  technician_cost NUMERIC NOT NULL CHECK (technician_cost >= 0),
   139→  -- Constraint: customer_price should be >= technician_cost * 2 (enforced in app logic)
   140→  
   141→  -- Technician assignment
   142→  technician_id TEXT REFERENCES public.users(user_id),
   143→  technician_commission_pct NUMERIC DEFAULT 0.50,  -- 50% by default
   144→  
   145→  -- Description
   146→  description TEXT NOT NULL,
   147→  detailed_notes TEXT,
   148→  time_spent_minutes INTEGER,
   149→  
   150→  -- Status
   151→  status TEXT NOT NULL DEFAULT 'completed' CHECK (status IN (
   152→    'scheduled', 'in_progress', 'completed', 'cancelled', 'billed'
   153→  )),
   154→  
   155→  -- Dates
   156→  scheduled_at TIMESTAMPTZ,
   157→  started_at TIMESTAMPTZ,
   158→  completed_at TIMESTAMPTZ DEFAULT now(),
   159→  billed_at TIMESTAMPTZ,
   160→  
   161→  -- Payment
   162→  payment_method TEXT CHECK (payment_method IN ('cash', 'bank_transfer', 'included_in_rental', 'deferred')),
   163→  payment_status TEXT DEFAULT 'unpaid' CHECK (payment_status IN ('unpaid', 'paid', 'partial', 'waived')),
   164→  paid_at TIMESTAMPTZ,
   165→  
   166→  -- Audit
   167→  created_by TEXT NOT NULL,
   168→  created_at TIMESTAMPTZ DEFAULT now(),
   169→  updated_at TIMESTAMPTZ DEFAULT now()
   170→);
   171→
   172→-- Indexes
   173→CREATE INDEX idx_service_operations_crew ON public.service_operations(crew_id);
   174→CREATE INDEX idx_service_operations_vehicle ON public.service_operations(vehicle_id);
   175→CREATE INDEX idx_service_operations_rental ON public.service_operations(rental_id);
   176→CREATE INDEX idx_service_operations_technician ON public.service_operations(technician_id);
   177→CREATE INDEX idx_service_operations_completed_at ON public.service_operations(completed_at DESC);
   178→
   179→-- RLS Policies
   180→ALTER TABLE public.service_operations ENABLE ROW LEVEL SECURITY;
   181→
   182→-- Crew members can read their crew's operations
   183→CREATE POLICY "Crew members can read service operations" 
   184→  ON public.service_operations FOR SELECT
   185→  USING (
   186→    crew_id IN (
   187→      SELECT crew_id FROM public.crew_members
   188→      WHERE user_id = auth.uid()
   189→    )
   190→    OR EXISTS (
   191→      SELECT 1 FROM public.users
   192→      WHERE users.user_id = auth.uid()
   193→      AND (users.metadata->>'role')::text = 'admin'
   194→    )
   195→  );
   196→
   197→-- Crew owners and admins can manage
   198→CREATE POLICY "Crew owners can manage service operations"
   199→  ON public.service_operations FOR ALL
   200→  USING (
   201→    EXISTS (
   202→      SELECT 1 FROM public.crews
   203→      WHERE crews.id = service_operations.crew_id
   204→      AND crews.owner_id = auth.uid()
   205→    )
   206→    OR EXISTS (
   207→      SELECT 1 FROM public.users
   208→      WHERE users.user_id = auth.uid()
   209→      AND (users.metadata->>'role')::text = 'admin'
   210→    )
   211→  );
   212→
   213→COMMENT ON TABLE public.service_operations IS 'Service operations tracking for all crews. Customer price typically = 2x technician cost.';
   214→```

   302→### 2.4 Table: `public.cash_transactions`
   303→
   304→**Purpose:** Единый реестр всех денежных движений для экипажа
   305→
   306→```sql
   307→-- Migration: 20260809000003_create_cash_transactions.sql
   308→
   309→CREATE TABLE public.cash_transactions (
   310→  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
   311→  crew_id UUID NOT NULL REFERENCES public.crews(id) ON DELETE CASCADE,
   312→  
   313→  -- Transaction type
   314→  transaction_type TEXT NOT NULL CHECK (transaction_type IN (
   315→    'income_rental',       -- Доход от аренды
   316→    'income_sale',         -- Доход от продажи
   317→    'income_service',      -- Доход от услуг сервиса
   318→    'income_equipment',    -- Доход от аренды оборудования
   319→    'expense_salary',      -- Расход на зарплату
   320→    'expense_commission',  -- Комиссия менеджеру
   321→    'expense_tech_work',   -- Оплата техники
   322→    'expense_cashout',     -- Расход из кассы (перевод)
   323→    'expense_other',       -- Другие расходы
   324→    'transfer_in',         -- Входящий перевод
   325→    'transfer_out'         -- Исходящий перевод
   326→  )),
   327→  
   328→  -- Amount
   329→  amount NUMERIC NOT NULL,
   330→  currency TEXT DEFAULT 'RUB',
   331→

   336→  
   337→  -- Flow direction

   339→  
   340→  -- Links to entities
   341→  rental_id UUID REFERENCES public.rentals(rental_id) ON DELETE SET NULL,
   342→  sale_contract_id UUID,  -- References private.sale_contract_artifacts(id)
   343→  service_operation_id UUID REFERENCES public.service_operations(id) ON DELETE SET NULL,
   344→  equipment_rental_id UUID REFERENCES public.equipment_rentals(id) ON DELETE SET NULL,
   345→  
   346→  -- Counterparties
   347→  from_user_id TEXT REFERENCES public.users(user_id),
   348→  to_user_id TEXT REFERENCES public.users(user_id),
   349→  recipient_name TEXT,  -- For external recipients
   350→  recipient_bank TEXT,
   351→  
   352→  -- Categorization
   353→  category TEXT,
   354→  subcategory TEXT,
   355→  tags TEXT[],
   356→  
   357→  -- Status
   358→  status TEXT DEFAULT 'completed' CHECK (status IN ('pending', 'completed', 'cancelled', 'reversed')),
   359→  
   360→  -- Dates
   361→  transaction_date TIMESTAMPTZ NOT NULL DEFAULT now(),
   362→  value_date TIMESTAMPTZ,
   363→  
   364→  -- Documents
   365→  document_url TEXT,
   366→  receipt_number TEXT,
   367→  
   368→  -- Description
   369→  description TEXT NOT NULL,
   370→  notes TEXT,
   371→  
   372→  -- Balance snapshots (optional)
   373→  cash_balance_before NUMERIC,
   374→  cash_balance_after NUMERIC,
   375→  bank_balance_before NUMERIC,
   376→  bank_balance_after NUMERIC,
   377→  
   378→  -- Audit
   379→  created_by TEXT NOT NULL,
   380→  created_at TIMESTAMPTZ DEFAULT now(),
   381→  updated_at TIMESTAMPTZ DEFAULT now()
   382→);
   383→
   384→-- Indexes
   385→CREATE INDEX idx_cash_transactions_crew ON public.cash_transactions(crew_id);
   386→CREATE INDEX idx_cash_transactions_type ON public.cash_transactions(transaction_type);
   387→CREATE INDEX idx_cash_transactions_date ON public.cash_transactions(transaction_date DESC);
   388→CREATE INDEX idx_cash_transactions_rental ON public.cash_transactions(rental_id);
   389→CREATE INDEX idx_cash_transactions_flow ON public.cash_transactions(flow_direction);
   390→CREATE INDEX idx_cash_transactions_category ON public.cash_transactions(category);
   391→
   392→-- RLS
   393→ALTER TABLE public.cash_transactions ENABLE ROW LEVEL SECURITY;
   394→
   395→CREATE POLICY "Crew members can read transactions"
   396→  ON public.cash_transactions FOR SELECT
   397→  USING (
   398→    crew_id IN (
   399→      SELECT crew_id FROM public.crew_members
   400→      WHERE user_id = auth.uid()
   401→    )
   402→    OR EXISTS (
   403→      SELECT 1 FROM public.users
   404→      WHERE users.user_id = auth.uid()
   405→      AND (users.metadata->>'role')::text = 'admin'
   406→    )
   407→  );
   408→
   409→-- View: Daily Cash Flow Summary per Crew
   410→CREATE OR REPLACE VIEW public.daily_cash_flow AS
   411→SELECT
   412→  crew_id,
   413→  DATE(transaction_date) as date,
   414→  transaction_type,
   415→  flow_direction,
   416→  SUM(amount) as total_amount,
   417→  COUNT(*) as transaction_count,
   418→  payment_method
   419→FROM public.cash_transactions
   420→WHERE status = 'completed'
   421→GROUP BY crew_id, DATE(transaction_date), transaction_type, flow_direction, payment_method;
   422→
   423→COMMENT ON TABLE public.cash_transactions IS 'Unified cash flow ledger for all crews';
   424→```

   946→### 3.3 Calculate Manager Commission on Rental Completion
   947→
   948→```sql
   949→-- Migration: 20260809000010_trigger_rental_commission.sql
   950→
   951→CREATE OR REPLACE FUNCTION public.calculate_rental_commission()
   952→RETURNS TRIGGER AS $$
   953→DECLARE
   954→  v_commission_pct NUMERIC;
   955→  v_commission_amount NUMERIC;
   956→  v_manager_id TEXT;
   957→BEGIN
   958→  IF NEW.status = 'completed' AND OLD.status != 'completed' THEN
   959→    -- Get commission rate for this crew
   960→    SELECT commission_value INTO v_commission_pct
   961→    FROM public.commission_rates
   962→    WHERE crew_id = NEW.crew_id
   963→      AND operation_type = 'rental_hourly'
   964→      AND CURRENT_DATE BETWEEN valid_from AND COALESCE(valid_until, CURRENT_DATE)
   965→    ORDER BY priority DESC
   966→    LIMIT 1;
   967→    
   968→    v_commission_pct := COALESCE(v_commission_pct, 0.10);  -- Default 10%
   969→    v_commission_amount := NEW.total_cost * v_commission_pct;
   970→    
   971→    -- Get crew owner (manager)
   972→    SELECT owner_id INTO v_manager_id
   973→    FROM public.crews
   974→    WHERE id = NEW.crew_id;
   975→    
   976→    -- Create commission transaction
   977→    INSERT INTO public.cash_transactions (
   978→      transaction_type,
   979→      amount,
   980→      flow_direction,
   981→      category,
   982→      description,
   983→      rental_id,
   984→      to_user_id,
   985→      crew_id,
   986→      created_by
   987→    )
   988→    VALUES (
   989→      'expense_commission',
   990→      v_commission_amount,
   991→      'out',
   992→      'Комиссия',
   993→      'Комиссия с аренды #' || SUBSTRING(NEW.rental_id::TEXT FROM 1 FOR 8),
   994→      NEW.rental_id,
   995→      v_manager_id,
   996→      NEW.crew_id,
   997→      auth.jwt() ->> 'chat_id'
   998→    );
   999→  END IF;
  1000→  
  1001→  RETURN NEW;
  1002→END;
  1003→$$ LANGUAGE plpgsql;
  1004→
  1005→DROP TRIGGER IF EXISTS trg_rental_commission ON public.rentals;
  1006→CREATE TRIGGER trg_rental_commission
  1007→  AFTER UPDATE OF status ON public.rentals
  1008→  FOR EACH ROW
  1009→  EXECUTE FUNCTION public.calculate_rental_commission();
  1010→```

  1148→## 5. DATA MIGRATION STRATEGY
  1149→
  1150→### 5.1 Backfill Service Operations from Rentals
  1151→
  1152→```sql
  1153→-- Extract service operations from existing rentals with service metadata
  1154→INSERT INTO public.service_operations (
  1155→  operation_type,
  1156→  rental_id,
  1157→  vehicle_id,
  1158→  customer_price,
  1159→  technician_cost,
  1160→  description,
  1161→  crew_id,
  1162→  status,
  1163→  completed_at,
  1164→  created_by
  1165→)
  1166→SELECT
  1167→  'tuning' as operation_type,
  1168→  r.rental_id,
  1169→  r.vehicle_id,
  1170→  (r.metadata->>'service_price')::NUMERIC,
  1171→  (r.metadata->>'service_price')::NUMERIC * 0.5,
  1172→  r.metadata->>'service_description',
  1173→  r.crew_id,
  1174→  'completed',
  1175→  r.updated_at,
  1176→  r.owner_id
  1177→FROM public.rentals r
  1178→WHERE r.metadata->>'service_description' IS NOT NULL
  1179→  AND NOT EXISTS (
  1180→    SELECT 1 FROM public.service_operations so
  1181→    WHERE so.rental_id = r.rental_id
  1182→  );
  1183→```
  1184→
  1185→### 5.2 Backfill Cash Transactions from Rentals
  1186→
  1187→```sql
  1188→-- Rental income transactions
  1189→INSERT INTO public.cash_transactions (
  1190→  transaction_type,
  1191→  amount,
  1192→  flow_direction,
  1193→  payment_method,
  1194→  rental_id,
  1195→  category,
  1196→  description,
  1197→  crew_id,
  1198→  transaction_date,
  1199→  status,
  1200→  created_by
  1201→)
  1202→SELECT
  1203→  'income_rental',
  1204→  r.total_cost,
  1205→  'in',
  1206→  COALESCE((r.metadata->>'payment_method'), 'cash'),
  1207→  r.rental_id,
  1208→  'Аренда',
  1209→  'Аренда ' || (SELECT model FROM public.cars WHERE id = r.vehicle_id),
  1210→  r.crew_id,
  1211→  r.created_at,
  1212→  'completed',
  1213→  r.owner_id
  1214→FROM public.rentals r
  1215→WHERE r.status IN ('completed', 'active')
  1216→  AND NOT EXISTS (
  1217→    SELECT 1 FROM public.cash_transactions ct
  1218→    WHERE ct.rental_id = r.rental_id
  1219→      AND ct.transaction_type = 'income_rental'
  1220→  );
  1221→```
