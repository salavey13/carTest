    11→    11→## 1. EXECUTIVE SUMMARY
    12→    12→
    13→    13→### 1.1 Problem Statement
    14→    14→
    15→    15→Сервисы экипажей (VIP BIKE, NNVolt, и др.) нуждаются в унифицированной системе учета:
    16→    16→
    17→    17→- **Доходы:** аренда байков, продажа услуг сервиса, аренда оборудования (шлемы)
    18→    18→- **Расходы:** зарплата сотрудников (механики, менеджеры), переводы из кассы
    19→    19→- **Зарплата:** расчет ЗП с бонусами от аренды/продаж/услуг сервиса с выплатами 10 и 25 числа
    20→    20→- **Ежедневная отчетность:** для ассистента и владельца экипажа
    21→    21→- **Оборудование:** учет выдачи шлемов и экипировки (требуется новая таблица `equipment_rentals`, т.к. `rental_handoffs` не существует)
    22→    22→
    23→    23→### 1.2 Current Architecture Analysis
    24→    24→
    25→    25→#### ✅ Existing Tables (from `supabase.txt` snapshot 2026-07-23):
    26→    26→
    27→    27→**Public Schema:**
    28→    28→```sql
    29→    29→-- Crews & Members
    30→    30→public.crews                    -- id, slug, name, owner_id, theme
    31→    31→public.crew_members             -- id, crew_id, user_id, role (owner|co_owner|admin|mechanic|member)
    32→    32→public.users                    -- user_id, username, full_name, metadata->role
    33→    33→
    34→    34→-- Catalog & Rentals
    35→    35→public.cars                     -- id, make, model, type ('bike'|'accessories'), specs->sale_price, specs->rent_weekday_hour
    36→    36→public.rentals                  -- rental_id, crew_id, vehicle_id, user_id, status, total_cost, metadata->service_description
    37→    37→
    38→    38→-- Private Schema (PII & Contracts)
    39→    39→private.user_rental_secrets     -- chat_id, crew_slug, passport data, STS pledge
    40→    40→private.rental_contract_artifacts -- contract_key, rental_id, crew_slug, PDF storage_path
    41→    41→private.sale_contract_artifacts   -- contract_key, buyer_*, sale_price, warranty_months, crew_slug
    42→    42→```
    43→    43→
    44→    44→#### ❌ Identified Gaps:
    45→    45→
    46→    46→1. **NO `service_operations` table** — услуги сервиса (сборка, настройка, ремонт) хранятся только в `rentals.metadata->service_description` без структуризации
    47→    47→2. **NO `equipment_rentals` table** — шлемы и оборудование не имеют отдельного финансового учета аренды
    48→    48→3. **NO `cash_transactions` ledger** — доходы/расходы разрознены по таблицам, нет единого cash flow
    49→    49→4. **NO `commission_rates` configuration** — ставки комиссий менеджерам не настраиваются гибко
    50→    50→5. **NO `salary_plans` with payout schedule** — нет плана ЗП с привязкой к 10 и 25 числам
    51→    51→6. **NO `rental_handoffs` table** — выдача/возврат оборудования (шлемов) не отслеживается явно в БД
    52→    52→7. **NO `document_drafts` table** — состояние черновиков документов не сохраняется между сессиями
    53→    53→
    54→    54→#### ⚠️ Important Findings from Deep Investigation:
    55→    55→
    56→    56→- **`rental_handoffs` does NOT exist** in current schema (supabase.txt 2026-07-23) — выдача шлемов НЕ отслеживается на уровне БД
    57→    57→  - **Solution:** Create `public.equipment_rentals` table as single source of truth for equipment tracking
    58→    58→  - No need to create `rental_handoffs` — equipment rentals table is cleaner approach
    59→    59→  
    60→    60→- **`crew_member_shifts` FULLY EXISTS AND WORKS** ✅
    61→    61→  - Table structure confirmed: id, member_id, crew_id, clock_in_time, clock_out_time, duration_minutes (generated), hourly_rate, salary_amount, checkpoint (jsonb), actions (jsonb)
    62→    62→  - Trigger `trg_calc_shift_salary` auto-calculates salary on clock_out (BEFORE INSERT OR UPDATE OF clock_out_time)
    63→    63→  - Migration file: `app/wb/sql/shift_checkpoint.sql` adds checkpoint/actions JSONB columns
    64→    64→  - Bot command `/shift` implemented in `app/webhook-handlers/commands/shift.ts`
    65→    65→  - API endpoint `/api/crew/shifts` for CRUD operations (POST start, DELETE end, GET active)
    66→    66→  - **Integration:** Use existing `crew_member_shifts` table for base salary calculation in `salary_plans` via foreign key relationship
    67→    67→  
    68→    68→- **`document_drafts` does NOT exist** — doc-manual.ts state persistence needs new table (PRD #2 proposes this)
    69→    69→
    70→    70→- **"vip-bike" is a crew slug** — NEVER hardcoded; all paths use `[slug]` parameter ✅
    71→    71→
    72→    72→- **Existing sales-analytics** (`app/franchize/[slug]/sales-analytics/SalesAnalyticsClient.tsx`) shows `SaleDashboardItem` without delivery method field — needs update

   110→   110→
   111→   111→```sql

   115→   115→  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
   116→   116→  crew_id UUID NOT NULL REFERENCES public.crews(id) ON DELETE CASCADE,
   117→   117→

   120→   120→    'assembly',      -- Сборка (например Folkon GT)
   121→   121→    'tuning',        -- Настройка (ослабление цепи, регулировка)
   122→   122→    'repair',        -- Ремонт
   123→   123→    'maintenance',   -- ТО
   124→   124→    'installation',  -- Установка (колеса, суппорты)

   126→   126→    'inspection'     -- Диагностика
   127→   127→  )),
   128→   128→  
   129→   129→  -- Link to bike/equipment
   130→   130→  vehicle_id TEXT REFERENCES public.cars(id),
   131→   131→  equipment_ids TEXT[],  -- Array of equipment IDs (helmets, wheels)
   132→   132→  
   133→   133→  -- Link to rental (if service is part of rental)
   134→   134→  rental_id UUID REFERENCES public.rentals(rental_id) ON DELETE SET NULL,
   135→   135→  
   136→   136→  -- Financials
   137→   137→  customer_price NUMERIC NOT NULL CHECK (customer_price > 0),
   138→   138→  technician_cost NUMERIC NOT NULL CHECK (technician_cost >= 0),
   139→   139→  -- Constraint: customer_price should be >= technician_cost * 2 (enforced in app logic)
   140→   140→  
   141→   141→  -- Technician assignment
   142→   142→  technician_id TEXT REFERENCES public.users(user_id),
   143→   143→  technician_commission_pct NUMERIC DEFAULT 0.50,  -- 50% by default
   144→   144→  
   145→   145→  -- Description
   146→   146→  description TEXT NOT NULL,
   147→   147→  detailed_notes TEXT,
   148→   148→  time_spent_minutes INTEGER,
   149→   149→  
   150→   150→  -- Status
   151→   151→  status TEXT NOT NULL DEFAULT 'completed' CHECK (status IN (
   152→   152→    'scheduled', 'in_progress', 'completed', 'cancelled', 'billed'
   153→   153→  )),
   154→   154→  
   155→   155→  -- Dates
   156→   156→  scheduled_at TIMESTAMPTZ,
   157→   157→  started_at TIMESTAMPTZ,
   158→   158→  completed_at TIMESTAMPTZ DEFAULT now(),
   159→   159→  billed_at TIMESTAMPTZ,
   160→   160→  
   161→   161→  -- Payment
   162→   162→  payment_method TEXT CHECK (payment_method IN ('cash', 'bank_transfer', 'included_in_rental', 'deferred')),
   163→   163→  payment_status TEXT DEFAULT 'unpaid' CHECK (payment_status IN ('unpaid', 'paid', 'partial', 'waived')),
   164→   164→  paid_at TIMESTAMPTZ,
   165→   165→  
   166→   166→  -- Audit
   167→   167→  created_by TEXT NOT NULL,
   168→   168→  created_at TIMESTAMPTZ DEFAULT now(),
   169→   169→  updated_at TIMESTAMPTZ DEFAULT now()
   170→   170→);
   171→   171→
   172→   172→-- Indexes
   173→   173→CREATE INDEX idx_service_operations_crew ON public.service_operations(crew_id);
   174→   174→CREATE INDEX idx_service_operations_vehicle ON public.service_operations(vehicle_id);
   175→   175→CREATE INDEX idx_service_operations_rental ON public.service_operations(rental_id);
   176→   176→CREATE INDEX idx_service_operations_technician ON public.service_operations(technician_id);
   177→   177→CREATE INDEX idx_service_operations_completed_at ON public.service_operations(completed_at DESC);
   178→   178→
   179→   179→-- RLS Policies
   180→   180→ALTER TABLE public.service_operations ENABLE ROW LEVEL SECURITY;
   181→   181→
   182→   182→-- Crew members can read their crew's operations
   183→   183→CREATE POLICY "Crew members can read service operations" 
   184→   184→  ON public.service_operations FOR SELECT
   185→   185→  USING (
   186→   186→    crew_id IN (
   187→   187→      SELECT crew_id FROM public.crew_members
   188→   188→      WHERE user_id = auth.uid()
   189→   189→    )
   190→   190→    OR EXISTS (
   191→   191→      SELECT 1 FROM public.users
   192→   192→      WHERE users.user_id = auth.uid()
   193→   193→      AND (users.metadata->>'role')::text = 'admin'
   194→   194→    )
   195→   195→  );
   196→   196→
   197→   197→-- Crew owners and admins can manage
   198→   198→CREATE POLICY "Crew owners can manage service operations"
   199→   199→  ON public.service_operations FOR ALL
   200→   200→  USING (
   201→   201→    EXISTS (
   202→   202→      SELECT 1 FROM public.crews
   203→   203→      WHERE crews.id = service_operations.crew_id
   204→   204→      AND crews.owner_id = auth.uid()
   205→   205→    )
   206→   206→    OR EXISTS (
   207→   207→      SELECT 1 FROM public.users
   208→   208→      WHERE users.user_id = auth.uid()
   209→   209→      AND (users.metadata->>'role')::text = 'admin'
   210→   210→    )
   211→   211→  );
   212→   212→
   213→   213→COMMENT ON TABLE public.service_operations IS 'Service operations tracking for all crews. Customer price typically = 2x technician cost.';
   214→   214→```

   805→   805→-- Migration: 20260809000008_trigger_sync_rental_service.sql

   807→   807→CREATE OR REPLACE FUNCTION public.sync_rental_service_operation()
   808→   808→RETURNS TRIGGER AS $$
   809→   809→BEGIN
   810→   810→  -- If rental has service_description in metadata, create service_operation

   834→   834→      'completed',

   946→   946→### 3.3 Calculate Manager Commission on Rental Completion
   947→   947→
   948→   948→```sql
   949→   949→-- Migration: 20260809000010_trigger_rental_commission.sql
   950→   950→
   951→   951→CREATE OR REPLACE FUNCTION public.calculate_rental_commission()
   952→   952→RETURNS TRIGGER AS $$
   953→   953→DECLARE
   954→   954→  v_commission_pct NUMERIC;
   955→   955→  v_commission_amount NUMERIC;
   956→   956→  v_manager_id TEXT;
   957→   957→BEGIN
   958→   958→  IF NEW.status = 'completed' AND OLD.status != 'completed' THEN
   959→   959→    -- Get commission rate for this crew
   960→   960→    SELECT commission_value INTO v_commission_pct
   961→   961→    FROM public.commission_rates
   962→   962→    WHERE crew_id = NEW.crew_id
   963→   963→      AND operation_type = 'rental_hourly'
   964→   964→      AND CURRENT_DATE BETWEEN valid_from AND COALESCE(valid_until, CURRENT_DATE)
   965→   965→    ORDER BY priority DESC
   966→   966→    LIMIT 1;
   967→   967→    
   968→   968→    v_commission_pct := COALESCE(v_commission_pct, 0.10);  -- Default 10%
   969→   969→    v_commission_amount := NEW.total_cost * v_commission_pct;
   970→   970→    
   971→   971→    -- Get crew owner (manager)
   972→   972→    SELECT owner_id INTO v_manager_id
   973→   973→    FROM public.crews
   974→   974→    WHERE id = NEW.crew_id;
   975→   975→    
   976→   976→    -- Create commission transaction
   977→   977→    INSERT INTO public.cash_transactions (
   978→   978→      transaction_type,
   979→   979→      amount,
   980→   980→      flow_direction,
   981→   981→      category,
   982→   982→      description,
   983→   983→      rental_id,
   984→   984→      to_user_id,
   985→   985→      crew_id,
   986→   986→      created_by
   987→   987→    )
   988→   988→    VALUES (
   989→   989→      'expense_commission',
   990→   990→      v_commission_amount,
   991→   991→      'out',
   992→   992→      'Комиссия',
   993→   993→      'Комиссия с аренды #' || SUBSTRING(NEW.rental_id::TEXT FROM 1 FOR 8),
   994→   994→      NEW.rental_id,
   995→   995→      v_manager_id,
   996→   996→      NEW.crew_id,
   997→   997→      auth.jwt() ->> 'chat_id'
   998→   998→    );
   999→   999→  END IF;
  1000→  1000→  
  1001→  1001→  RETURN NEW;
  1002→  1002→END;
  1003→  1003→$$ LANGUAGE plpgsql;
  1004→  1004→
  1005→  1005→DROP TRIGGER IF EXISTS trg_rental_commission ON public.rentals;
  1006→  1006→CREATE TRIGGER trg_rental_commission
  1007→  1007→  AFTER UPDATE OF status ON public.rentals
  1008→  1008→  FOR EACH ROW
  1009→  1009→  EXECUTE FUNCTION public.calculate_rental_commission();

  1149→  1149→
  1150→  1150→### 5.1 Backfill Service Operations from Rentals
  1151→  1151→
  1152→  1152→```sql
  1153→  1153→-- Extract service operations from existing rentals with service metadata
  1154→  1154→INSERT INTO public.service_operations (
  1155→  1155→  operation_type,
  1156→  1156→  rental_id,
  1157→  1157→  vehicle_id,
  1158→  1158→  customer_price,
  1159→  1159→  technician_cost,
  1160→  1160→  description,
  1161→  1161→  crew_id,
  1162→  1162→  status,
  1163→  1163→  completed_at,
  1164→  1164→  created_by
  1165→  1165→)
  1166→  1166→SELECT
  1167→  1167→  'tuning' as operation_type,
  1168→  1168→  r.rental_id,
  1169→  1169→  r.vehicle_id,
  1170→  1170→  (r.metadata->>'service_price')::NUMERIC,
  1171→  1171→  (r.metadata->>'service_price')::NUMERIC * 0.5,
  1172→  1172→  r.metadata->>'service_description',
  1173→  1173→  r.crew_id,
  1174→  1174→  'completed',
  1175→  1175→  r.updated_at,
  1176→  1176→  r.owner_id
  1177→  1177→FROM public.rentals r
  1178→  1178→WHERE r.metadata->>'service_description' IS NOT NULL
  1179→  1179→  AND NOT EXISTS (
  1180→  1180→    SELECT 1 FROM public.service_operations so
  1181→  1181→    WHERE so.rental_id = r.rental_id
  1182→  1182→  );
  1183→  1183→```
