# Расследование: ответ клиенту Avito из веб-приложения (rental CRM)

> Дата: 2026-09-05 · Статус: расследование завершено, вердикт — **возможно**, есть 2 гейта
> Связь: PLAN-2026-09-05 (B5/C5), качество-тест ответов (385af4f)

## Целевой поток (как хочет владелец)

1. Сообщение Avito извлечено монитором → лид в CRM → GLM-анализ
2. Telegram-уведомление команде: текст + «Контекст» + **deeplink на лид**
3. Оператор открывает лид: инфо + «Подготовка» + «Готовый ответ» → жмёт «ОК»
4. Ответ **отправляется в чат Avito** из веб-приложения

## Возможность отправки: проверено живыми пробами

- Эндпоинт существует: `POST /messenger/v1/accounts/{user_id}/chats/{chat_id}/messages` (только текст; есть image-вариант, удаление ≤1ч, `chatRead`).
- **client_credentials-токен → HTTP 403 «invalid access token»** (проба sale-профиля, фейковый chat_id): отправлять от сервисного токена нельзя.
- **User-токен (Authorization Code) уже есть** в `secrets.env` (`.tokens.json`), но со scope **`messenger:read`** — для отправки нужен **`messenger:write`**.
- OAuth-обвязка готова: колбэк `https://marketing.vip-bike.ru/avito/callback` работает, refresh_token сохраняется → перегенерация токена с расширенным scope — штатная процедура.
- **Аренда: HTTP 402** (нет подписки Messenger API) — на чтение. Действует ли 402 на отправку — неизвестно, проверится только write-токеном. Продажа: чтение 200, отправка ожидаемо заработает.

## Рекомендуемая архитектура отправки (секреты не покидают фабрику)

```
CRM (rental.vip-bike.ru)                 Фабрика (marketing.vip-bike.ru)
«Готовый ответ» → [Отправить в Avito]    POST /avito/send (secret = AVITO_LEADS_WEBHOOK_SECRET)
   └─ server action ──────────────────►    └─ user-token messenger:write →
                                              POST messenger/v1/.../messages
                                              + лог в SQLite (direction=out)
                                          ◄── 200 {ok} / 4xx {error}
```

Почему релей, а не токены на rental VPS: креды Avito остаются на фабрике рядом с монитором (одна точка ротации), CRM не хранит секреты, лог отправок живёт в одной БД с историей диалогов.

Обязательные гарды отправки (риск бана Avito):
- только ответы в существующих u2i-чатах, никогда первое сообщение;
- запрет одинакового текста разным чатам подряд (уникализация черновиков уже решает);
- per-chat cooldown (например ≤5 сообщений/час) и глобальный дневной потолок;
- идемпотентность кнопки (single-flight, disable на время отправки), при ошибке — фоллбек «скопируйте и отправьте вручную».

## Deeplink-цепочка (шаг 2→3) — как достроить

- В репо уже есть Telegram startapp-роутер: `app/lib/startapp-handler.ts`
  (`rent_…`, `cart_<base64>` → redirectPath). Паттерн переиспользуется: новый префикс
  `lead_<id>` → redirect `/franchize/vip-bike/leads?lead=<id>`.
- `LeadsClient` (1247 строк): добавить чтение `?lead=` и `setSelectedId` после загрузки
  лидов (шторка ищет по `l.user_id`).
- Нюанс идентичности: у avito-лидов `franchize_intents.user_id` может быть пустым
  (webhook не ставит user_id) — надёжнее deeplink по `metadata.avitoChatId`:
  `GET /api/leads/by-chat?chat_id=…` → 302 на страницу лида.
- Монитор: в `format_notification` добавить кнопку/ссылку «Открыть лид» (web-URL или
  `t.me/<бот>?startapp=lead_…`, если карточки открывают в мини-апп бота).

## Гейты (нужны владельцу)

1. **OAuth re-auth с scope `messenger:write`** — перейти по authorize-ссылке фабрики,
   подтвердить в Avito под аккаунтом профилей. До этого отправка невозможна технически.
2. **Подписка Messenger API для аренды** — влияет и на чтение (402), возможно и на отправку.
3. **Решение по релею** — согласие, что отправки ходят через фабричный сервер.
4. Политика безопасности: кто имеет право жать «Отправить» (роль оператора в CRM).

## Порядок внедрения (после гейтов)

1. OAuth write-токен → проба отправки на test-чат обоих профилей (фиксируем 402-гейт отправки аренды).
2. Фабричный релей `/avito/send` (секрет уже совпадает с webhook-секретом) + лог direction=out.
3. CRM: server action → релей; кнопка «Отправить в Avito» в шторке с фоллбеком копирования.
4. Deeplink-цепочка: `lead_…` в startapp-handler + `?lead=` в LeadsClient + «Открыть лид» в уведомлении монитора.
5. Анти-спам гарды + метрика «время от сообщения клиента до отправки» в B2-отчёт.
