3 Supabase: создаём все таблицы (схема)

В новом проекте база пустая — ни одной таблицы. Схема — это «чертёж» всех таблиц. Он у нас готов одним файлом. Просто вставь его целиком и запусти.

Скачай файл схемы: full-schema-2026-10-13.sql (правая кнопка → «Сохранить ссылку», это текстовый файл ~700 КБ).

В меню слева: SQL Editor → New query → открой скачанный файл блокнотом, выдели всё (Ctrl+A), скопируй (Ctrl+C), вставь в окно SQL Editor (Ctrl+V) → Run (или Ctrl+Enter).

create table users ( … );
create table crews ( … );

Проверка

Открой слева Table Editor. В списке таблиц должны появиться (среди прочих): users, crews, cars, crew_members, rentals, specs, posts, rental_contract_artifacts (в схеме private). Сотни штук — не пугайся, это нормально. Отдельные надписи «already exists» в логе — тоже норм, это повторные создания.

Альтернатива для гиков

Можно залить схему через CLI: npm i -g supabase → supabase login → supabase link --project-ref <REF> → supabase db push из папки репо (попросят Database Password из шага 2). Но способ с SQL Editor проще и не требует ничего ставить.

4.2. Перед первым деплоем: убрать лишний cron

Подводный камень — обязательно прочти

В файле vercel.json проекта прописано 3 расписания (cron). На бесплатном плане Vercel Hobby разрешено максимум 2 cron-задачи, лишние Vercel может встретить ошибкой деплоя. Лечится за минуту: в своём форке на GitHub открой vercel.json (кнопка-карандаш «Edit this file»), удали блок с "cleanup-wallpix-staging" целиком (это косметическая чистка, без неё всё работает), нажми Commit changes.

"crons": [
  { "path": "/api/fetch-crypto-prices",     "schedule": "0 0 * * *" },
  { "path": "/api/cron/wall-renter-notify", "schedule": "0 4 * * *" }
]

5.3. Как применить переменные

Магия слов: NEXT_PUBLIC_*

Все переменные, начинающиеся с NEXT_PUBLIC_, «впекаются» в сайт в момент сборки. Поменял их → недостаточно нажать Save, нужно пересобрать: вкладка Deployments → напротив последнего деплоя «⋯» → Redeploy → confirm. Остальные (без префикса) подхватятся и просто так, но Redeploy лишним не бывает.

6 Накатываем бэкап: данные и файлы

Схема есть, сайт вот-вот будет. Теперь заливаем содержимое: все аренды, байки, юзеров, экипажи, посты, настройки — и картинки/документы из хранилища.

6.1. Скачать бэкап (4 части + манифест)

Части по 40 МБ (лимит загрузки одного файла на бесплатном Supabase — 50 МБ, поэтому порезано):

Части архива (скачать ВСЕ 4 штуки в одну папку):

6.2. Склеить части обратно в zip

Открой терминал/командную строку в той папке, куда всё скачал:

# Windows (командная строка, cmd):
copy /b cartest-super-backup-20261013.zip.part0.bin+cartest-super-backup-20261013.zip.part1.bin+cartest-super-backup-20261013.zip.part2.bin+cartest-super-backup-20261013.zip.part3.bin cartest-super-backup-20261013.zip

# Mac / Linux (терминал):
cat cartest-super-backup-20261013.zip.part*.bin > cartest-super-backup-20261013.zip

Получится файл 132 649 008 байт. Контрольная сумма (если хочется проверить, что всё доехало):

Windows PowerShell: Get-FileHash cartest-super-backup-20261013.zip -Algorithm SHA256
Mac/Linux: sha256sum cartest-super-backup-20261013.zip

Должно сойтись: ef26b9ddedf80528155531648d6d7cc4e0ce0067bc51d90d1636d6a2849ca87d

Распакуй архив (двойной клик / «Extract All» / unzip cartest-super-backup-20261013.zip). Внутри — папка cartest-backup-202610131850.

6.3. Запуск рестора

Скачай код репо (зелёная кнопка Code → Download ZIP на твоём форке и распакуй, или git clone https://github.com/твой-ник/cartest). В папке репо:

# 1) поставить зависимости (нужен Node 20+; если есть bun — bun install)
npm install

# 2) запустить рестор (одна длинная команда):
node scripts/restore.mjs ^
  --url https://ТВОЙ-REF.supabase.co ^
  --key ТВОЙ-SERVICE_ROLE-KEY ^
  --dir C:\загрузки\cartest-backup-202610131850

# на Mac/Linux вместо ^ — \ в конце строк, или просто напиши в одну строку
Что скрипт делает

Создаёт storage-бакеты с теми же настройками → льёт все файлы → вставляет строки таблиц (сперва «родителей», потом зависимые; секретные таблицы private.* в конце). Скрипт можно перезапускать: что уже залилось, он пропустит. Если какая-то таблица упала по внешнему ключу — запусти ещё раз, а хвосты долей так: node scripts/restore.mjs --only имя_таблицы …

Проверка после рестора

Supabase → Table Editor: в cars — сотни байков, в rentals — аренды, в users — сотни юзеров. Storage: в бакете carpix — папки с картинками и PDF. Числа должны быть похожи на паспорт архива: 117 таблиц / 11 716 строк.

Чего в бэкапе НЕТ (и это нормально)

Пользователи авторизации (auth.users) — пароли/сессии Supabase не экспортируются в принципе. Все будут логиниться заново через Telegram-бота — это штатный путь этого проекта, ничего не теряется. Секреты Vercel/бота — ты их и так вписываешь руками (шаги 5 и 7). Договоры-DOCX в storage — оригинальные байты удалены из склада ещё до бэкапа (см. приложение); но данные всех договоров целы в таблице private.rental_contract_artifacts — приложение перегенерирует DOCX по шаблону одной кнопкой «Мой договор».

7 Телеграм-бот: BotFather

Бот — «дверь» в вебапп: по кнопке «Открыть приложение» Telegram открывает сайт, и человек логинится автоматически. Делаешь СВОЕГО бота — оригинальный остаётся у владельца.

7.1. Создание бота

  1. Открой в Telegram @BotFather → кнопка Start / команда /newbot.
  2. BotFather спросит имя — это человеческое название, любое: «Cartest Clone».
  3. Потом спросит юзернейм — должен кончаться на bot: например salavey_clone_bot.
  4. BotFather пришлёт токен вида 7712345678:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxx. СКОПИРУЙ его — это и есть TELEGRAM_BOT_TOKEN из шага 5. Если потерял — в BotFather команда /mybots → бот → API Token.

7.2. Вебхук (бот узнаёт о сообщениях)

Вебхук — это адрес, куда Telegram стучится, когда боту пишут. Открой в браузере ссылку (подставь свой токен и свой домен Vercel):

https://api.telegram.org/botТВОЙ_ТОКЕН/setWebhook?url=https://cartest-clone.vercel.app/api/telegramWebhook

Ответ должен быть {"ok":true,"result":true,"description":"Webhook was set"}. Всё.

8 Стать админом

После первого входа через бота ты появился в базе как обычный пользователь. Поднимаешь себя до глобального админа двумя строчками SQL.

  1. Зайди на сайт через кнопку меню бота (шаг 7) — так твоя строка появится в таблице users.
  2. Узнай свой Telegram ID (бот @userinfobot).
  3. Supabase → SQL Editor → New query → вставь и Run:
UPDATE users SET role = 'admin' WHERE user_id = ТВОЙ_TELEGRAM_ID;

Обнови страницу сайта — откроются админские разделы. Если нужно быть админом ещё и конкретного экипажа (роли owner / co_owner / admin дают доступ к франшизному кабинету):

UPDATE crew_members SET role = 'owner' WHERE user_id = ТВОЙ_TELEGRAM_ID AND crew_id = (
  SELECT id FROM crews WHERE slug = 'vip-bike');

9 Финальная проверка

Прогони по списку
  • Сайт открывается по адресу Vercel, шапка и картинки на месте (картинки = значит storage залился).
  • Каталог байков открывается, цены и фото показываются.
  • Вход через бота: кнопка меню → твой профиль, имя/аватар из Telegram.
  • Создай тестовую аренду: байк → даты → корзина → оформление → договор DOCX сгенерился и скачался.
  • Стена (community wall): посты прошлого сезона видны.
  • Карта (map-riders): райдеры/маршруты рисуются, тёмная/светлая тема переключает скин.
  • Уведомления: создай аренду — в твой чат прилетает сообщение от бота (значит TELEGRAM_SEND_MODE=direct работает).
  • Админка: раздел франшизы открывается (значит шаг 8 сработал).

Папка в архивеЧто там
data/*.jsonВсе 117 таблиц (109 public + 8 private), 11 716 строк, полные данные: байки, экипажи, юзеры, аренды, посты, артефакты договоров, секреты арендаторов (private.user_rental_secrets).

MANIFEST.jsonПаспорт: количество строк/файлов, коммит, контрольные суммы.
Про пропавшие договоры (orphaned)

В storage оригинального проекта числятся метаданные 266 договоров аренды и 287 документов из doc-verifier, у которых сами файлы уже удалены из склада (бэкап подтверждает: сервер отвечает «NoSuchKey»). Это мусорные строки, а не потеря данных: содержимое каждого договора целиком хранится в таблице private.rental_contract_artifacts, и приложение в любой момент перегенерирует DOCX по шаблону. В паспорте архива эти объекты честно перечислены как unrecoverable.

Секретность

В архиве паспорта, водительские удостоверения, телефоны и секреты экипажей. Держи его на своём диске, не выкладывай в публичные облака и не пересылай непонятно кому. Скачал, восстановил — архив можно удалить или скинуть на зашифрованную флешку.
