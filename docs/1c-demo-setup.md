# Демо-стенд 1С для cartTest — пошаговая инструкция

> Цель: за вечер поднять на своём Windows-ПК полноценную 1С, сконфигурить демо-каталог
> «Запчасти» + HTTP-сервис «megarepo», открыть программный доступ (OData + HTTP-сервисы)
> и подключить это к коннектору из `lib/connectors/onec` в репе `carTest` (ветка/подсистема franchize).
>
> Время: ~1,5–2 часа. Бюджет: 0 ₽ (бесплатная комьюнити-лицензия разработчика).
> Всё в одном файле: каждый клик расписан, код модуля — готовый copy-paste.

---

## 0. Что мы строим (30 секунд на понимание)

```
[Next.js dev: npm run dev → localhost:3000]
        │  fetch + Basic auth
        ▼
[IIS (localhost:80)]  ← публикация ИБ «demo1c»
        │
        ▼
[Файловая ИБ 1С «demo1c»]
   ├─ HTTP-сервис «megarepo»   ← канал записи (ping / orders / documents)
   └─ Справочник «Запчасти»    ← каталог, читается через OData
```

Коннектор в cartTest (`lib/connectors/onec/client.ts`) ждёт ровно такой контракт:

| Канал | Эндпоинт на стороне 1С | Ответ |
|---|---|---|
| HTTP-сервис (запись) | `GET  /hs/megarepo/ping` | `{ "ok": true }` (любой JSON) |
| HTTP-сервис (запись) | `POST /hs/megarepo/orders` | `{ "ref": "...", "number": "...", "alreadyExisted": false }` |
| HTTP-сервис (запись) | `GET  /hs/megarepo/documents/{ref}` | JSON документа |
| OData (чтение) | `GET /odata/standard.odata/Catalog_Запчасти?$format=json&$top=5` | коллекция `{ "value": [...] }` |

Переменные окружения, которые потом пропишем в cartTest (`.env.local`):

```bash
ONC_BASE_URL=http://localhost/demo1c
ONC_USERNAME=svc_cartest
ONC_PASSWORD=SuperDemo123!
ONC_SERVICE_NAME=megarepo
```

Заметка: коннектор также понимает `ONEC_BASE_URL` как алиас, а `ONC_SERVICE_NAME`
по умолчанию = `megarepo`. Время ожидания ответа — 15 секунд (таймаут зашит в коннекторе).

## 1. Шаг 1. Аккаунт на developer.1c.ru + комьюнити-лицензия

Комьюнити-лицензия — официальная бесплатная лицензия 1С для разработки. Это **полноценная
платформа** (не урезанная «учебная версия»): работает и файловый, и клиент-серверный режим,
веб-публикация, HTTP-сервисы и OData — всё как в боевой. Ограничения только лицензионные:
только для разработки (не для прод-эксплуатации), лицензия живёт 7 дней и автопродлевается,
на один аккаунт — до 3 лицензий, платформа шлёт на серверы 1С телеметрию использования.

1. Открой в браузере `https://developer.1c.ru`.
2. В правом верхнем углу нажми **ВХОД**.
3. Если аккаунта нет — нажми ссылку **«Нет логина?»** под формой входа.
4. Заполни регистрационную форму (ФИО, e-mail) и подтверди почту по письму.
5. Обязательно подтверди **номер мобильного телефона** — без этого комьюнити-лицензию
   не выдаст (это единственная «неудобная» часть регистрации).
6. После входа открой консоль лицензий:
   `https://developer.1c.ru/applications/Console?state=community`
7. В списке лицензий нажми **«Активировать комьюнити-лицензию»** (сначала список пуст — это норм).
8. Там же, на портале разработчиков, скачай дистрибутив **Технологической платформы 8.3
   версии 8.3.23 или новее** (Windows, полный установщик x64). Раздел загрузок доступен
   прямо из консоли — отдельно ничего покупать не нужно.

> Проверка: у тебя на руках установщик вида `1cv83_x64_<версия>.exe` (или rar) и
> активная комьюнити-лицензия в консоли.

## 2. Шаг 2. Установка платформы на Windows

1. Запусти установщик **от имени администратора** (ПКМ → «Запуск от имени администратора»).
2. Мастер установки → **Далее** → выбор компонентов. Отметь:
   - **1С:Предприятие** (обязательно — тонкий/толстый клиент);
   - **1С:Предприятие — thin client** (опционально);
   - **Администрирование сервера 1С:Предприятия** (опционально, для файлового стенда не критично);
   - ⚠️ **Модуль расширения веб-сервера** — ОБЯЗАТЕЛЬНО. Без него IIS не сможет
     обслуживать публикацию, и весь шаг с OData/HTTP-сервисами умрёт на старте.
3. Язык интерфейса: **Русский** → Далее → Установить.
4. Установка идёт в `C:\Program Files\1cv8\<версия>\` — запомни путь, он понадобится
   при публикации (там лежит модуль `wsisapi.dll`).
5. Перезагрузка не обязательна, но если установщик попросит — соглашайся.

## 3. Шаг 3. Создание пустой информационной базы «demo1c»

1. Пуск → в поиске набери **«1С:Предприятие»** → открой ярлык (список баз пуст — ок).
2. Нажми **Добавить…**
3. Выбери **«Создание новой информационной базы»** → Далее.
4. Выбери **«Создание информационной базы без конфигурации»** (самый нижний пункт списка шаблонов) → Далее.
5. Имя базы: `demo1c` → Далее.
6. Каталог информационной базы: `C:\1C_Bases\demo1c` (папка создастся сама, если нажать «Создать» в диалоге) → Далее → **Готово**.
7. Выдели базу в списке и нажми **Конфигуратор** (не «1С:Предприятие» — сначала конфигурируем).

> Справка: файловая ИБ = всё лежит в папке `C:\1C_Bases\demo1c`. Для демо-стенда этого
> достаточно, сервер СУБД не нужен.

## 4. Шаг 4. Справочник «Запчасти» (демо-каталог)

Работаем в Конфигураторе базы `demo1c`.

1. В дереве конфигурации (справа) нажми ПКМ на корень → **«Открыть конфигурацию»**.
2. Раскрой ветку **Справочники** → ПКМ → **Добавить**.
3. Откроется конструктор справочника. Вкладка **Основные**:
   - Имя: `Запчасти` (кириллица — нормально; в OData объект станет `Catalog_Запчасти`);
   - Синоним заполнится сам: «Запчасти»;
   - Представление объекта: «Запчасть», списка: «Запчасти» (автоматом, можно не трогать).
4. Вкладка **Иерархия**: «Не использовать» (плоский список — проще для теста).
5. Вкладка **Данные**:
   - Длина кода: `9`;
   - Длина наименования: `150`;
   - Основное представление: «В виде наименования».
6. Вкладка **Данные** → в списке реквизитов нажми **Добавить реквизит** и создай по очереди
   (имена — латиницей, чтобы в OData-фильтрах не маячить с URL-кодированием):

   | Имя | Синоним | Тип | Длина/точность |
   |---|---|---|---|
   | `Article` | Артикул | Строка | 50 |
   | `Price` | Цена | Число | 15, точность 2, «Неотрицательное» ✔ |
   | `Stock` | Остаток | Число | 10, точность 0 |
   | `Unit` | Ед. изм. | Строка | 10 |
   | `Category` | Категория | Строка | 50 |

7. Вкладка **Прочее**: галка «Стандартные команды» должна стоять (чтобы справочник видно было в интерфейсе).
8. Нажми **F7** (или Конфигурация → «Обновить конфигурацию базы данных») → Принять.
9. Нажми **F5** (Запуск отладки / «Начать отладку») — откроется режим «1С:Предприятие».
10. В режиме Предприятие: слева **Запчасти** → **Создать** → заведи 5–10 тестовых позиций,
    например:

    | Наименование | Артикул | Цена | Остаток | Ед. | Категория |
    |---|---|---|---|---|---|
    | Тормозной диск передний Surge | SRG-BR-001 | 4200 | 12 | шт | Тормоза |
    | Тормозные колодки задние Surge | SRG-BR-002 | 1800 | 30 | шт | Тормоза |
    | Цепь привода 420H | SRG-DR-010 | 1250 | 25 | шт | Драйв |
    | Контроллер 48V 25A | SRG-EL-003 | 8900 | 6 | шт | Электрика |
    | Аккумулятор 48V 13Ah | SRG-EL-011 | 24900 | 4 | шт | Электрика |

11. Закрой режим Предприятие — возвращаемся в Конфигуратор.

## 5. Шаг 5. Документ «ЗаказКлиента» (для канала записи megarepo)

Контракт `upsertOrder` шлёт в 1С заказ с `externalId`, контрагентом и строками. В пустой
конфигурации документа нет — создадим простой «приёмник», который хранит то, что прислал cartTest.

1. В Конфигураторе: ветка **Документы** → ПКМ → **Добавить**.
2. Вкладка **Основные**: Имя: `ЗаказКлиента` (в OData будет `Document_ЗаказКлиента` —
   ровно как в юнит-тестах коннектора).
3. Вкладка **Данные** → «Стандартные реквизиты» оставляем как есть, добавляем **реквизиты**:

   | Имя | Тип | Длина |
   |---|---|---|
   | `ExternalId` | Строка | 36 |
   | `CounterpartyName` | Строка | 150 |
   | `CounterpartyPhone` | Строка | 20 |
   | `Total` | Число | 15,2 |
   | `Comment` | Строка | 0 (неограниченная) |

4. Там же, во вкладке **Данные**, нажми **«Табличные части» → Добавить**:
   - Имя табличной части: `Lines`.
5. Внутри `Lines` создай реквизиты:

   | Имя | Тип | Длина/точность |
   |---|---|---|
   | `Sku` | Строка | 50 |
   | `Name` | Строка | 150 |
   | `Quantity` | Число | 10,3 |
   | `Price` | Число | 15,2 |

6. Индексируем `ExternalId` (чтобы поиск по нему был быстрым): реквизит `ExternalId`
   → свойства → **Индексировать = «Индексировать»**.
7. **F7** (обновить конфигурацию БД).

## 6. Шаг 6. Роль и пользователь для интеграции

1. Конфигуратор → ветка **Общие** → **Роли** → ПКМ → **Добавить** → Имя: `ИнтеграционныеПрава`.
2. Открой роль двойным кликом, справа появится дерево «Все объекты». Для демо-стенда
   проще всего дать полные права (прод-харднинг сделаем позже):
   - поставь галку на корне **«Все объекты»** (включит всё во всём дереве).
3. **F7** → сохраняем конфигурацию (Ctrl+S).
4. Теперь пользователь. Режим Предприятие из конфигуратора: **F5** → в открытом окне:
   **Администрирование → Пользователи → Создать**:
   - ФИО / Имя: `svc_cartest`;
   - Аутентификация: **«Аутентификация 1С:Предприятия»** ✔, пароль `SuperDemo123!`
     (галку «Пользователю запрещено изменять пароль» можно поставить);
   - «Аутентификация OpenID» и «Аутентификация операционной системы» — **выключены**;
   - Права доступа: отметить роль `ИнтеграционныеПрава`;
   - Записать и закрыть.
5. Закрой сеанс Предприятия (он держит базу и иногда мешает публикации).

> Почему отдельный пользователь: Basic-auth коннектора идёт именно с `ONC_USERNAME/ONC_PASSWORD`,
> и лучше, чтобы у этого логина не было человеческих прав «всё ломать» и отдельного
> аудита. Для локального демо роль «всё на всё» — ок.

## 7. Шаг 7. HTTP-сервис «megarepo» (готовый код)

1. Конфигуратор → ветка **Общие** → **HTTP-сервисы** → ПКМ → **Добавить**.
2. Вкладка **Основные**: Имя: `megarepo`.
3. Вкладка **Корневой URL** (или поле «Корневой URL» в основных, зависит от версии
   конфигуратора): **Корневой URL: `megarepo`**. Важно: коннектор строит адрес
   `{baseUrl}/hs/{serviceName}/...`, где serviceName — это именно корневой URL публикации.
4. Вкладка **Адресное пространство** (шаблоны URL) → **Добавить → Новый шаблон URL**:
   - Имя шаблона: `Ping`, Шаблон: `/ping` — методы: добавь **GET**, обработчик создастся
     автоматически (двойной клик по методу → лупа → «Создать обработчик»);
   - Аналогично шаблон `Orders`, Шаблон: `/orders`, метод **POST**;
   - Аналогично шаблон `Documents`, Шаблон: `/documents/{ref}`, метод **GET**.
5. Открой модуль HTTP-сервиса (ПКМ по сервису → «Открыть модуль») и вставь целиком:

```bsl
// ============================================================
// HTTP-сервис megarepo — контракт коннектора cartTest
// (lib/connectors/onec, см. lib/connectors/README.md):
//   GET  /hs/megarepo/ping             → {"ok":true}
//   POST /hs/megarepo/orders           → {"ok":true,"ref":..,"number":..,"alreadyExisted":..}
//   GET  /hs/megarepo/documents/{ref}  → JSON документа
// ============================================================

Функция PingGET(Запрос)
        Ответ = Новый HTTPСервисОтвет(200);
        Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
        Ответ.УстановитьТелоИзСтроки("{\"ok\":true,\"service\":\"megarepo\"}");
        Возврат Ответ;
КонецФункции

Функция OrdersPOST(Запрос)
        Попытка
                ТелоСтрокой = Запрос.ПолучитьТелоКакСтроку();
                Чтение = Новый ЧтениеJSON;
                Чтение.УстановитьСтроку(ТелоСтрокой);
                Данные = ПрочитатьJSON(Чтение, Ложь);

                ВнешнийID = "";
                Если Данные.Свойство("externalId") Тогда
                        ВнешнийID = Строка(Данные.externalId);
                КонецЕсли;
                Если ПустаяСтрока(ВнешнийID) Тогда
                        Возврат ОшибкаJSON(400, "externalId is required");
                КонецЕсли;

                Существующий = НайтиЗаказПоВнешнемуID(ВнешнийID);
                Если Существующий <> Неопределено Тогда
                        Возврат РезультатJSON(200, Существующий, Истина);
                КонецЕсли;

                Заказ = Документы.ЗаказКлиента.СоздатьДокумент();
                Заказ.ExternalId = ВнешнийID;
                Заказ.Дата = ТекущаяДатаСеанса();

                Если Данные.Свойство("counterparty") Тогда
                        Контрагент = Данные.counterparty;
                        Если Контрагент.Свойство("name") Тогда
                                Заказ.CounterpartyName = Строка(Контрагент.name);
                        КонецЕсли;
                        Если Контрагент.Свойство("phone") Тогда
                                Заказ.CounterpartyPhone = Строка(Контрагент.phone);
                        КонецЕсли;
                КонецЕсли;

                Если Данные.Свойство("comment") Тогда
                        Заказ.Comment = Строка(Данные.comment);
                КонецЕсли;

                Если Данные.Свойство("lines") И ТипЗнч(Данные.lines) = Тип("Массив") Тогда
                        Для Каждого СтрокаЗапроса Из Данные.lines Цикл
                                НоваяСтрока = Заказ.Lines.Добавить();
                                Если СтрокаЗапроса.Свойство("sku") Тогда
                                        НоваяСтрока.Sku = Строка(СтрокаЗапроса.sku);
                                КонецЕсли;
                                Если СтрокаЗапроса.Свойство("name") Тогда
                                        НоваяСтрока.Name = Строка(СтрокаЗапроса.name);
                                КонецЕсли;
                                Если СтрокаЗапроса.Свойство("quantity") Тогда
                                        НоваяСтрока.Quantity = Число(СтрокаЗапроса.quantity);
                                КонецЕсли;
                                Если СтрокаЗапроса.Свойство("price") Тогда
                                        НоваяСтрока.Price = Число(СтрокаЗапроса.price);
                                КонецЕсли;
                        КонецЦикла;
                КонецЕсли;

                Если Данные.Свойство("total") Тогда
                        Заказ.Total = Число(Данные.total);
                Иначе
                        // Сосчитаем сумму по строкам, если total не прислали
                        Сумма = 0;
                        Для Каждого СтрокаТЧ Из Заказ.Lines Цикл
                                Сумма = Сумма + СтрокаТЧ.Quantity * СтрокаТЧ.Price;
                        КонецЦикла;
                        Заказ.Total = Сумма;
                КонецЕсли;

                Заказ.Записать(РежимЗаписиДокумента.Запись);

                Возврат РезультатJSON(200, Заказ.Ссылка, Ложь);
        Исключение
                Возврат ОшибкаJSON(500, ОписаниеОшибки());
        КонецПопытки;
КонецФункции

Функция НайтиЗаказПоВнешнемуID(ВнешнийID)
        ЗапросПоиска = Новый Запрос;
        ЗапросПоиска.Текст = "ВЫБРАТЬ Заказ.Ссылка КАК Ссылка
                |ИЗ Документ.ЗаказКлиента КАК Заказ

        Возврат Неопределено;

Функция РезультатJSON(Код, Ссылка, УжеБыл)
        Ответ = Новый HTTPСервисОтвет(Код);
        Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");

        Запись = Новый ЗаписьJSON;
        Запись.УстановитьСтроку();
        Запись.НачатьОбъект();
        Запись.ЗаписатьИмяСвойства("ok");
        Запись.ЗаписатьЗначение(Истина);
        Запись.ЗаписатьИмяСвойства("ref");
        Запись.ЗаписатьЗначение(Строка(Ссылка.УникальныйИдентификатор()));
        Запись.ЗаписатьИмяСвойства("number");
        Запись.ЗаписатьЗначение(Ссылка.Номер);
```

## 8. Шаг 8. Включаем IIS в Windows

1. **Пуск → Панель управления → Программы → Программы и компоненты →
   «Включение или отключение компонентов Windows»**.
2. В дереве найди **«Службы IIS»** и поставь галку. Раскрой и убедись, что внутри отмечено:
   - **Средства управления веб-сайтом → Консоль управления IIS**;
   - **Службы Интернета → Общие функции HTTP** (статическое и динамическое содержимое, перенаправление HTTP);
   - **Службы Интернета → Компоненты разработки приложений → Расширения ISAPI** и **Фильтры ISAPI**;
   - **Службы Интернета → Компоненты наблюдения за работоспособностью** (журналы).
3. **ОК** → ждать установки (1–3 мин).
4. Проверка: открой `http://localhost` в браузере — должна появиться синяя страница IIS.

> Если «Службы IIS» в списке нет (редкие сборки Windows) — используй Windows 10/11
> Pro/Home, там IIS есть по умолчанию в составе компонентов.

## 9. Шаг 9. Публикация базы на веб-сервере (OData + HTTP-сервисы)

1. Конфигуратор → меню **Администрирование → Публикация на веб-сервере…**
2. Заполни:
   - Имя: `demo1c`;
   - Каталог публикации: `C:\inetpub\wwwroot\demo1c` (папка создастся сама);
   - Веб-сервер: **Internet Information Services**, платформа **64 бита** (если ставил x64-платформу);
   - Галка **«Публиковать стандартный интерфейс OData»** ✔;
   - Галка **«Публиковать HTTP-сервисы»** ✔ и в списке сервисов отметить `megarepo`;
   - Галка **«Разрешить аутентификацию 1С:Предприятия на веб-сервере»** ✔ (это Basic-auth,
     которым пользуется коннектор).
3. Нажми **Опубликовать**. Если спросит про установку/регистрацию модуля расширения
   веб-сервера — соглашайся (потребуются права администратора).
4. Открой cmd и перезапусти IIS: `iisreset`.

## 10. Шаг 10. Состав OData (что именно отдаём наружу)

1. Конфигуратор → **Администрирование → Стандартный интерфейс OData**.
2. В окне состава: если список пуст — нажми **«Добавить» → «Все объекты»** (для стенда ок),
   либо точечно добавь `Справочник.Запчасти` и `Документ.ЗаказКлиента`.
3. **F7** → обновить конфигурацию БД. Если публиковал раньше — зайди в
   «Публикация на веб-сервере» и нажми **Опубликовать** ещё раз + `iisreset`.

> Именно на этом шаге определяется, что `Catalog_Запчасти` будет доступен снаружи.
> Без включённого состава OData вернёт 404 на коллекцию.

## 11. Шаг 11. Smoke-тесты из командной строки

Открой PowerShell (не обязательно админ) и прогони по очереди. Везде замени пароль на свой.

## 13. Траблшутинг

| Симптом | Причина | Лечение |
|---|---|---|
| `401 Unauthorized` на `/hs/...` и `/odata/...` | На веб-сервере не включена аутентификация 1С, неверный пароль, у пользователя включена ОС-аутентификация | Перепубликуй с галкой «Разрешить аутентификацию 1С:Предприятия», проверь пароль, у `svc_cartest` выключи «Аутентификация ОС» |
| `404` на `/hs/megarepo/ping` | Сервис не попал в публикацию или корневой URL ≠ `megarepo` | Конфигуратор → Публикация → галка «Публиковать HTTP-сервисы» + отметить `megarepo` → Опубликовать → `iisreset` |
| `404` на `Catalog_Запчасти` (odata) | Пустой состав OData или не включён интерфейс | Администрирование → Стандартный интерфейс OData → добавить объекты → F7 → перепубликовать |
| IIS отдаёт `500.19` / `500` | Модуль расширения веб-сервера не зарегистрирован или битность пула не совпадает (32/64) | Переустанови платформу с компонентом «Модуль расширения веб-сервера»; IIS Manager → Application Pools → пул публикации → «Enable 32-Bit Applications» = False для x64 |
| IIS отдаёт `503` | Пул приложения остановлен | IIS Manager → Application Pools → Start у пула публикации |
| «Не обнаружен ключ защиты» при запуске | Комьюнити-лицензия протухла (7 дней) или нет интернета | Открой конфигуратор/клиент — лицензия переполучится автоматически при доступе в интернет; следи за слотами в консоли developer.1c.ru |
| Ошибка «Публикация недоступна» в конфигураторе | Конфигуратор запущен без прав администратора | Запусти Конфигуратор от админа |
| Кракозябры в ответах POST | Нет charset в Content-Type | Коннектор шлёт `application/json; charset=utf-8` — при ручных curl-тестах используй тот же заголовок |

## 14. Нюансы комьюнити-лицензии (короткая шпаргалка)

- Лицензия на 7 дней, автопродление при наличии интернета; на аккаунт — максимум 3
  активных слота (переактивация устройства после удаления задерживается на ~неделю).
- Только для разработки/отладки: нельзя крутить на ней реальный бизнес-контур.
- Платформа при использовании шлёт телеметрию на серверы 1С — для демо-каталога с
  тестовыми запчастями это не проблема, но боевые данные сюда не заносить.
- Клиент-серверный режим тоже работает (можно поднять локальный кластер 1С), но для
  текущего теста коннектора файловая база достаточна и надёжнее.
