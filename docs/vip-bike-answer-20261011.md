## ГОТОВЫЙ ТЕКСТ ДЛЯ ОТПРАВКИ

По пунктам, дружище 👇

**1. Мототех → продажи, Байкленд → экипировка: да, можно — и место есть.**
Витрина продавца = отдельный «экипаж» на платформе, как у вас vip-bike. Техника и экип в каталоге уже живут в одной таблице: на платформе сейчас 277 записей (у вас 147 из них: 32 байка + экипировка, услуги, даже подушки есть)). Так что сотни позиций мототеха и Байкленда встанут без вопросов — это обычные строки каталога.
Настройка: базовая витрина (товары + заявки уходят вам) — 1–2 дня. Данных с Авито и сайта на старте хватит: название, цена, фото — импортируем. Внутренние таблицы понадобятся, только когда захотите онлайн-брони и остатки — механика под байки уже готова (это наша система аренд), под экип — количество поддержано.
1С для мототеха — учиться коннектить надо, но это этап 2: стартуем на импорте с Авито/CSV, 1С подключим через обмен, когда пойдут обороты.

**2. Комиссия 5% с экипа и 1% с техники — норм для старта.**
Пока без онлайн-оплаты: лид уходит продавцу, сделку фиксируем, комиссию сводим раз в месяц по факту. Когда объёмы вырастут — автоматизируем, там же и 1С сойдётся.

**3. «Дальше все байкерские направления по городу и России» — да, модель копируется.**
Каждый новый продавец или город = новая витрина по одному чек-листу: товары → цены → фото → заявки. Карта райдеров и каталог уже мультиэкипажные — масштабируется без переделки ядра.

**4. Без ТГ это работает.**
Смотреть витрину, каталог и оставлять заявку можно из любого браузера — ТГ для этого не нужен: заявка падает оператору, он связывается сам. ТГ нужен только для профиля (вход, уведомления, история). Для тех, у кого «ТГ не работает» — сделаем вход по номеру телефона (SMS-код), это следующий этап: механика заявок уже сейчас от ТГ не зависит.

**5. Блогеры подсвечиваются на карте** — да, теперь видно, кто из райдеров активен, можно звать на коллабы прямо с карты.

## РАСШИРЕННАЯ ВНУТРЕННЯЯ ВЕРСИЯ (не отправлять)

### Q1 «Мототех к продажам и Байкленд к экипировке? Сколько места займут и настройка?»

- **Архитектура.** Каталог (`cars`) уже мультиарендный: каждая позиция принадлежит экипажу
  (`crew_id`), у экипажа свой slug/страница/карта. «Подключить продавца» = завести экипаж +
  залить товары. Никакой новой схемы БД на старте не нужно.
- **Объём.** Сейчас в таблице 277 строк на всю платформу (vip-bike — 147: 32 байка, 62 экипа,
  47 услуг, 6 wb-позиций). Postgres спокойно тянет сотни тысяч строк — узкое место не объём,
  а качество карточек (фото/описания).
- **Настройка.**
  - Этап 1 (1–2 дня на продавца): витрина + заявка-лид (имя/телефон/товар), лид падает
    оператору продавца. Импорт CSV из Авито/сайта (название, цена, фото, описание).
  - Этап 2 (по обороту): онлайн-брони/резервы (для техники уже есть rentals), остатки
    (`quantity` уже поддержан), взаиморасчёты комиссии.
- **Данных с Авито/сайта хватит?** Для витрины и лидов — да. Для броней и финансов —
  понадобятся внутренние таблицы, но они уже есть под байки; под экип добавить флаги продажи.

### Q2 «Комиссия 5% с экипа и 1% с техники — норм?»

- Нормальная точка входа для первого мультипродавца: ниже, чем Авито (авито берёт заметно
  больше с категорий техники), для клиента — почти безболезненно.
- Проверка экономики: 1% с байка за 200 000 ₽ = 2 000 ₽ с сделки; 5% с экипа за 15 000 ₽ =
  750 ₽. Чтобы закрыть операционку (импорт, модерация, поддержка), нужно ~N сделок/мес —
  посчитаем на цифрах мототеха после пилота.
- Схема без кассы: свод раз в месяц по зафиксированным сделкам (источник — лиды платформы,
  подтверждение — продавец). Дальше автосписание/эквайринг — этап 3.

### Q3 «Дальше все байкерские направления в городе и по России»

- Модель копируется: экипаж-витрина на город/нишу (мотозапчасти, шлемы, туризм…). Ядро
  (каталог + заявки + карта + аренда) общее — на каждый город заводится только контент.
- Слабое место не код, а операционка онбординга: чек-лист продавца (фото, цены, правила
  возврата, ответ на лид за N минут) — его стоит оформить сразу, чтобы масштаб не убил качество.

### Q4 «Без ТГ работает? Как сделать без привязки к ТГ»

- Работает: витрина/каталог/заявка — публичные веб-страницы, открываются с любого устройства.
- ТГ нужен для: профиля клиента, уведомлений, истории аренд (как Пол ответил — «тг для профиля
  нужен»).
- План Б для «не работает ТГ» (старые телефоны/сети): вход по телефону + SMS-код, уведомления
  на email/WhatsApp. Заявка оператору уже сейчас уходит без ТГ у клиента.
- Технически: аутентификация по телефону — стандартная задача (Supabase Auth phone), но это
  новый этап, не блокер для подключения мототеха/Байкленда.
