# Свой лендинг — свой бот: гайд «дальше» для экипажа

> Кейс: тебе отдали лендинг (например, `/leorus` — ивент-агентство LEORUS).
> Ты хочешь **свою** копию: свой деплой на Vercel, свой Telegram-бот,
> лендинг как Mini App внутри бота — и чтобы заявки с формы приходили
> **от твоего бота** тебе (и тем, кого ты укажешь).
> Да, схема ровно та, что звучит в одном предложении: *форк → Vercel →
> свой бот → токен в env → Web App в BotFather → уведомления из твоего бота*.
> Ниже — как сделать это правильно, без граблей.

---

## Схема целиком

```
 GitHub-форк (salavey13/carTest)
        │  import
        ▼
 Vercel — твой деплой (https://твой-лендинг.vercel.app)
   │  env: TELEGRAM_BOT_TOKEN (ТВОЙ бот), SUPABASE_*, ADMIN_CHAT_ID (твой chat id)
   │
   ├── форма лендинга POST /api/franchize/callback-lead
   │        │  резолвит получателей из БД (crews → owner/admins/members) + ADMIN_CHAT_ID
   │        ▼
   └── Telegram Bot API ← ТВОЙ токен → сообщения приходят ОТ ТВОЕГО бота

 @BotFather: /newapp → https://твой-лендинг.vercel.app/leorus
        │
        ▼
 Кнопка «Открыть приложение» в твоём боте = твой лендинг внутри Telegram
```

Замкнутый круг: бот ведёт на лендинг, лендинг шлёт заявки через бота.

---

## Шаг 1. Форк репозитория

1. Открой `github.com/salavey13/carTest` → **Fork** → «Copy the main branch only» можно оставить включённым.
2. Получишь `github.com/<ты>/carTest`. Дальше все правки — в своём форке, оригинал тебе мешать не будет.

Правка, которая понадобится почти сразу: экипаж, к которому привязана форма.
В лендинге `/leorus` slug зашит в `app/leorus/LeorusLandingClient.tsx`
(константа `slug: "djorudjov"`, примерно строка 95). Замени на **свой** slug —
или создай в своей БД экипаж с тем же слагом (см. шаг 2).

## Шаг 2. База: свой Supabase (или общий — решай осознанно)

Форма лендинга — не просто «отправить на почту»: сервер резолвит получателей
через Supabase (`crews`, `crew_members`) и пишет лид в БД. Варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Свой проект Supabase** (free tier хватает) | полная независимость; свои экипажи; чужие не видят твои лиды | нужно прогнать миграции и завести экипаж |
| Общая БД (ключи из текущего деплоя) | ноль настройки | лиды пишутся в общую таблицу; получатели — владелец экипажа из ОБЩЕЙ БД; для «свой бизнес» — неправильно |

Для своего проекта:

1. `supabase.com` → **New project** (регион ближе к аудитории, пароль БД сохрани).
2. SQL Editor → выполни миграции из `supabase/migrations/` репо (по порядку имен файлов) — там схема crews/leads/rentals.
3. Заведи свой экипаж с нужным slug (минимум: строка в `crews` с `slug`, `owner_id` = твой Telegram user id в виде текста) — по образцу сидов `docs/crewDocs/`.
4. Settings → API: сохрани три значения — Project URL, `anon` key, `service_role` key (понадобятся в шаге 4).

## Шаг 3. Свой Telegram-бот

1. Telegram → **@BotFather** → `/newbot` → имя (например, «LEORUS События») → username (должен кончаться на `bot`).
2. BotFather пришлёт **токен** вида `7712345678:AAE...` — это и есть `TELEGRAM_BOT_TOKEN`.
3. Узнай свой chat id: напиши боту **@userinfobot** — он ответит числом (например `123456789`). Это `ADMIN_CHAT_ID`.
4. **Важно (правило Telegram):** бот может писать только тем, кто сам нажал `/start` в его диалоге. Хочешь слать уведомления партнёру — пусть он сначала откроет твоего бота и нажмёт Start. Тот же механизм работает и для групп: добавь бота в группу и используй id группы (`-100...`) как `ADMIN_CHAT_ID`.

## Шаг 4. Деплой на Vercel

1. `vercel.com` → **Add New → Project** → импортируй свой форк. Framework: Next.js определится сам, настройки по умолчанию.
2. До первого деплоя открой **Environment Variables** и добавь минимум:

| Переменная | Значение | Зачем |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 2 | база |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key | клиент Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key | серверные операции (лиды, уведомления) |
| `TELEGRAM_BOT_TOKEN` | токен ТВОЕГО бота из шага 3 | **от кого** уходят уведомления |
| `ADMIN_CHAT_ID` | твой chat id (или id группы) | кому дублировать всё, плюс fallback-получатель |
| `NEXT_PUBLIC_SITE_URL` | `https://<твой-проект>.vercel.app` | публичный адрес для ссылок/ди поинтеров |

3. **Deploy**. Через пару минут у тебя будет адрес вида `https://твой-проект.vercel.app` — открой `/leorus`, проверь что лендинг живой.

Ключевой момент твоего вопроса — да: **уведомления уходят от того бота, чей
токен лежит в `TELEGRAM_BOT_TOKEN` деплоя**. Отправка идёт через
`lib/telegram-transport.ts` (`api.telegram.org/bot<ТОКЕН>/sendMessage`),
а получателей собирает `resolveLeadNotifyRecipients(slug)` из
`app/franchize/lib/new-lead-notify.ts`: владелец экипажа + админы + активные
участники из БД + `ADMIN_CHAT_ID`. Никакого «жёсткого» бота из оригинала в
цепочке нет — токен берётся из окружения твоего деплоя.

## Шаг 5. Пришить лендинг к боту как Web App (Mini App)

1. В **@BotFather** → `/mybots` → выбери своего бота → **Bot Settings → Menu Button** → «Configure menu button» → вставь `https://твой-проект.vercel.app/leorus`. (Альтернатива: `/newapp` — то же самое + иконка и описание для полного Mini App.)
2. Telegram требует HTTPS — Vercel даёт его из коробки, ничего настраивать не надо.
3. Открой диалог со своим ботом: слева от поля ввода появится кнопка меню — тап открывает **твой лендинг внутри Telegram**. На мобиле — нативное окно, на десктопе — Web App-панель.

Заметь: адрес в Menu Button можно вести и на внутреннюю страницу
(`.../leorus`), не только на корень — так у одного бота могут жить
несколько витрин (лендинг, каталог, история аренд).

## Шаг 6. Проверка «под ключ»

1. Нажми `/start` своему боту (тем аккаунтам, кто должен получать заявки, — тоже).
2. Открой Menu Button → лендинг → заполни форму → «Отправить заявку».
3. В диалоге с ботом приходит карточка лида (имя, телефон, формат, бюджет) — **от твоего бота**.
4. Мобильная проверка: тот же флоу в Telegram на телефоне — Mini App открывается в нативном окне.

## Грабли, о которых стоит знать заранее

- **«Бот молчит»** — почти всегда нарушение правила из шага 3: получатель не нажал `/start` этому боту. Бот не может написать первым.
- **Форма отвечает ошибкой** — проверь `SUPABASE_SERVICE_ROLE_KEY` (без него серверные операции отключены) и что экипаж с нужным slug существует в БД.
- **Заявки приходят не тому** — получатели резолвятся по slug из формы (`crews.owner_id`, админы, участники). Смени slug в клиенте или поправь `owner_id` в своей БД.
- **Общий чат экипажа** — вместо личных chat id удобно указать в БД участником экипажа групповой чат (id `-100...`): уведомления падают всем сразу.
- **Кастомный домен** — в Vercel: Settings → Domains → подключи свой; затем обнови URL в Menu Button бота и `NEXT_PUBLIC_SITE_URL`.
- **Обновления форка** — оригинал развивается: добавляй `salavey13` как upstream (`git remote add upstream …`) и раз в пару недель подтягивай `git fetch upstream && git merge upstream/main`, чтобы получать фиксы лендингов.
