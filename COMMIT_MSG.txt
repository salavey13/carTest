fix: deposit balance section + /ekip cancel bug + Russian date pickers + skill author guidance

Four parallel fixes from the user's investigation feedback.

# 1. deposit_entries timing verification — confirmed working

  The user saw "Aug 8: -10000 ₽ returned, +0 ₽ collected" and wondered
  why the collection wasn't shown. Verified via Supabase:

    - rental 9c0ba304 was CREATED 2026-07-31 11:04:14 UTC
    - deposit_entries deposit_collected row: 2026-07-31 11:04:14
      (same second as rental creation — collected via /doc flow)
    - deposit_entries deposit_returned row: 2026-08-08 17:44:03
      (when rental status → completed)

  So the deposits page IS working correctly. The collection happened on
  July 31 (rental creation day), the return on Aug 8 (rental completion day).
  The user was checking Aug 7 expecting to see +10000 — that was the wrong
  date. Page behavior confirmed correct.

# 2. /ekip cancel button → "Неизвестная кнопка" bug

  Root cause: handleEkipCallback in ekip-manual.ts checked
  `if (!ekipState) return false;` BEFORE handling the "cancel" callback.
  When the user's ekip state had been cleared (e.g. by an error in an
  earlier step, or by eq_done moving state forward), clicking "❌ Отменить"
  would fall through to handleDocCallback (no doc state either) → fall
  through to the "unrouted callback_query" branch → "Неизвестная кнопка.

  Используй /help или /doc."

  Fix in two places:
    - ekip-manual.ts: moved the `cancel` and `restart` handlers ABOVE
      the state check. Now they always succeed even with no state.
    - command-handler.ts: added a top-level fallback — any unrouted
      callback whose data is "cancel" or "restart" gets a graceful
      "❌ Отменено." response + state cleanup, instead of the confusing
      "Неизвестная кнопка" message. Catches the edge case where the
      flow's state has been cleared by expiry or a prior error but the
      user still sees a stale keyboard.

# 4. Part 3: deposit-balance API + on-hand balance UI section

  New API route: GET /api/franchize/deposit-balance?slug=<slug>
    - Returns all-time aggregate per destination (cash/tbank/sber):
      collected - returned - penalty = onHand
    - Auth: cookie-based, owner / co_owner / admin tier (deposits are
      sensitive financial data).
    - Filters by the crew's rental_ids (deposit_entries has no crew_id).

  Updated DepositsAdminClient.tsx with a new "Сейчас на руках (за всё
  время)" section at the TOP of the page (accent-colored to visually
  distinguish it from the per-day section below). Shows:
    - Per-destination card with the on-hand amount in big text
    - Below: "Получено: +X / Возвращено: -Y / Удержания: -Z" small text
    - Below all cards: "Итого на руках: <total>" if non-zero

  The existing per-day section ("За день: 19.08.2026") remains below
  for "what happened on this date" queries. The user can now answer
  BOTH "how much do we currently hold?" (top) and "what happened today?"
  (bottom).

# 5. All franchize date pickers now show Russian dd.mm.yyyy hint

  Native <input type=date> uses the browser's locale for display. Users
  with en-US locale (e.g. Telegram WebApp in English) see "08/07/2026"
  which a Russian user reads as "8th of July" instead of "7th of August".

  Since we can't override the browser's date input display format, added
  a small "(dd.mm.yyyy)" label next to each date input showing the
  selected date in unambiguous Russian format. The user always knows
  what date they're actually viewing/selecting.

  Created app/franchize/components/DateInputRu.tsx with:
    - formatDateRu(iso) helper: "2026-08-19" → "19.08.2026"
    - formatDateRuLong(iso) helper: "2026-08-19" → "19 авг. 2026 г."
    - DateInputRu component: wraps <input type=date> + shows the
      Russian-format hint next to it

  Applied the format-hint pattern (manually, since the existing date
  inputs use different styling per page) to:
    - app/franchize/[slug]/salary/SalaryClient.tsx (2 inputs)
    - app/franchize/[slug]/profile/ProfileClient.tsx (2 inputs)
    - app/franchize/[slug]/cash-ledger/CashLedgerClient.tsx (2 inputs)
    - app/franchize/[slug]/admin/deposits/DepositsAdminClient.tsx (1 input + already used formatDateRu for the "За день" header)
    - app/franchize/[slug]/equipment/EquipmentClient.tsx (1 input)
    - app/franchize/[slug]/rentals-analytics/RentalsAnalyticsClient.tsx (1 input)
    - app/franchize/[slug]/rentals-analytics/ExportModal.tsx (2 inputs)

  The todos page already had its own formatDateInput doing dd.mm.yyyy
  — no change needed.

  Modals (Item.tsx, SubrentFlowClient.tsx) are operator-only flows
  with less user impact — left as-is for now (can be patched in a
  follow-up if needed).
