fix(shift+doc): shift money timing bug + /doc rental row never created (missing crew_id)

Three critical fixes from user's testing feedback.

# 1. /shift close: money line was never shown (closure timing bug)

  Root cause: userMessage was constructed INSIDE the switch/case block
  BEFORE shiftLogAction() ran. shiftEarnedAmount was set inside the async
  shiftLogAction closure, which only executed LATER at line 182
  (`if (shiftLogAction) await shiftLogAction();`). By the time the
  closure set shiftEarnedAmount, userMessage was already set with
  shiftEarnedAmount=0 → moneyLine was always "\n" (no money shown).

  User tested after commit 4972f392 and got:
    "✅ Смена завершена. Хорошего отдыха!"
  (no 💰 line — because shiftEarnedAmount was 0 when the message was built)

  Fix: replaced inline userMessage construction with a `needClockOutMessage`
  flag. After `await shiftLogAction()` completes (where shiftEarnedAmount
  gets populated), the message is constructed with the correct amount:

  ```js
  if (shiftLogAction) await shiftLogAction();
  if (needClockOutMessage) {
      const moneyLine = shiftEarnedAmount > 0
        ? `\n💰 Заработано: ${shiftEarnedAmount.toLocaleString("ru-RU")} ₽ (${shiftEarnedHours} ч × ${shiftEarnedRate} ₽/ч)\n`
        : "\n";
      userMessage = `✅ Смена завершена.${moneyLine}\nХорошего отдыха!`;
  }
  ```

# 2. /doc: rental row never created (missing crew_id in insert)

  Root cause: createRentalFromDocContract in doc-manual.ts inserted into
  the `rentals` table WITHOUT setting `crew_id`. The table requires it
  (or the insert silently failed via constraint violation / RLS).

  Verified via Supabase: the rental_contract_artifacts table has an entry
  from today (17:34 UTC = 20:34 Moscow, renter "Шонов Дмитрий Николаевич")
  but `rental_id = null` — the artifact was saved but no rentals row was
  created. 0 rentals in the last 12 hours.

  Fix: added `crew_id: effectiveCrewId` to the rentalInsert object.
