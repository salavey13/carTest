# PRD — vip-bot (VIP BIKE Telegram-бот)

## Цель
Оператор VIP BIKE оформляет договор аренды электробайка прямо в Telegram за минуты, не заводя клиента вручную «по старинке». Бот распознаёт документы и генерирует готовый юридический `.docx`.

## Пользователи
Операторы проката (Рустам, Илья) — доступ по `ALLOWED_CHAT_ID`. Посторонние игнорируются.

## Фичи (поведенческие критерии)

### F1. Агент договоров (скилл `contract-agent`) — ядро фазы 1
- **Дано:** оператор пишет «новый договор» и присылает фото паспорта + ВУ + параметры (байк, срок, тариф, депозит).
- **Поведение:** бот сохраняет фото → распознаёт через `recognize` CLI → показывает поля в чат на подтверждение/правку → по «ок» генерирует `.docx` (№ `VB-YYYY-NNN`, sha256, запись в SQLite) → отдаёт файл в чат → чистит фото.
- **Готово когда:** в чат приходит корректный `.docx` без сырых `{{плейсхолдеров}}`, с МСК-датами; запись в SQLite есть; исходные фото удалены.
- **Edge:** нет какого-то параметра → бот спрашивает одним сообщением; плохое фото → просит перефото; пустые обязательные поля → не отдаёт битый docx, показывает чего не хватает.

### F2. Контроль доступа
- Только операторы из `ALLOWED_CHAT_ID`. Иначе — без ответа.

### F3. Штатные lean-скиллы KLOD-BOX (вторично)
- Транскрибация голосовых, напоминания/расписание, отправка файлов — из коробки рантайма. Не основной скоуп, но доступны.

### F4. 152-ФЗ
- Фото документов не хранятся в БД (только распознанные поля). После генерации — удаление из `workspace/uploads/`. Согласие на ПДн — пункт договора.

## Вне скоупа фазы 1
- Купля-продажа (отдельная форма — позже). Онлайн-оплата. PDF из docx (только если клиент попросит — через LibreOffice на VPS). Веб-кабинет.

## Боевой режим — нужны данные клиента ({{уточнить}})
Реквизиты `lessor`; тарифы/депозит/прайс повреждений + адрес возврата; per-unit `bike_units` (VIN/год/цвет); `Z_AI_API_KEY`+модель; `TELEGRAM_BOT_TOKEN`+операторы; VPS-доступ.
