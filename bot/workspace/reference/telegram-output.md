# Вывод в Telegram — файлы, пути, ограничения

## Прислать файл в чат — тег `<file>`

Оберни **абсолютный путь** в `<file>`:
```
Готово:
<file>/opt/claudeclaw/workspace/uploads/post-1.png</file>
```
С подписью:
```
<file caption="Слайд 1">/opt/claudeclaw/workspace/uploads/post-1.png</file>
```

Бот сам: определит тип по расширению (`.png/.jpg`→фото, `.mp4`→видео, `.mp3/.ogg`→аудио, иначе документ), удалит тег из текста, лимит 50MB/файл. Несколько тегов = несколько файлов. >50MB → в Google Drive (skill `publish-to-cloud`) + ссылка.

## Пост + картинка — НЕ дублируй текст

Caption ≤ 1024 символа. ОДИН вариант:

**A — короткий пост (≤1000) в caption:**
```
<file caption="⚡ [весь пост]">/path/img.jpg</file>
```
**B — длинный пост в тексте, фото без caption:**
```
[весь пост]

<file>/path/img.jpg</file>
```
ЗАПРЕЩЕНО: одинаковый текст и в теле, и в `caption` — пользователь увидит дубль.

## Создал файл — всегда указывай путь

В финальном сообщении — относительный путь:
```
Готово. Файл: workspace/second-brain/INBOX/2026-05-03-plan.md
```
Не пиши «выше/сохранил/записал» без пути — в Telegram нет «выше».

## Не base64-ь файлы для API

- ЗАПРЕЩЕНО: `base64 file | curl -d ...` — Claude Code обрежет вывод на 32KB, зациклишься.
- ПРАВИЛЬНО: `curl -F "file=@/path"` (multipart) или Composio с `file_path`.
- Маленький текст (≤30KB) → строкой через `jq --arg`, не base64.
- Признак цикла: повторное чтение `tool-results/*.txt` или длинные `PCFET0NUWVBF...` в bash → стоп, другой способ.
