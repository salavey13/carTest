# Напоминания

Создание напоминания через локальный CLI. Без этого скилла модель НЕ ИМЕЕТ права обещать напоминания.

## Жёсткое правило

Если пользователь просит напоминание — ты ОБЯЗАН:
1. Узнать текущее время через `Bash: date '+%Y-%m-%d %H:%M %z'`
2. Посчитать cron-выражение
3. Дёрнуть `schedule-cli` через Bash (см. команду ниже)
4. Сообщить пользователю реальный ID задачи и время следующего срабатывания

ЗАПРЕЩЕНО писать «поставил, напомню в HH:MM» без успешного выполнения CLI. Это враньё.

## Команда

```bash
# chat_id берём из PRIMARY_CHAT_ID (если задан), иначе первый из ALLOWED_CHAT_ID
CHAT="${PRIMARY_CHAT_ID:-$(echo "$ALLOWED_CHAT_ID" | cut -d, -f1)}"
node dist/schedule-cli.js create "ТЕКСТ_НАПОМИНАНИЯ" "CRON" "$CHAT"
```

Путь относительный — `dist/schedule-cli.js` запускается из директории сервиса (systemd `WorkingDirectory`). НЕ пиши абсолютные пути типа `/opt/claudeclaw/...` — они зависят от инсталляции.

## Конвертация запроса в cron

| Запрос | Логика | Cron |
|---|---|---|
| «через 30 минут» | `date` + 30 мин → конкретные `M H D Mon` | например `45 19 14 5 *` |
| «в 21:00» (сегодня) | сегодняшняя дата + время | `0 21 14 5 *` |
| «в 18:30 и 18:50» | ДВЕ задачи — два `create` | два cron-выражения |
| «каждый день в 9 утра» | повторяющийся | `0 9 * * *` |
| «каждое утро в 8» | повторяющийся | `0 8 * * *` |
| «по понедельникам в 10» | повторяющийся | `0 10 * * 1` |
| «через час» | `date` + 1ч | конкретные `M H D Mon` |

**Разовые напоминания** (через X минут / в HH:MM сегодня) → конкретные `M H D Mon *`. После срабатывания сработает ещё раз через год — это нормально, потом удалишь.

**Повторяющиеся** (каждый день / каждое утро) → wildcards `* * *` в днях/месяцах.

## Полный цикл

Пользователь: «Напомни через 30 минут позвонить маме»

```
1. Bash: date '+%Y-%m-%d %H:%M %z'
   → "2026-05-14 19:15 +0300"
2. Считаем: +30 мин → 19:45, 14 мая
3. Cron: "45 19 14 5 *"
4. Bash:
   CHAT="${PRIMARY_CHAT_ID:-$(echo "$ALLOWED_CHAT_ID" | cut -d, -f1)}"
   node dist/schedule-cli.js create "Позвонить маме" "45 19 14 5 *" "$CHAT"
   → "Task created: abc-123-..."
5. Ответ пользователю: «Поставил на 19:45. Напомню текстом.»
```

## Если несколько напоминалок

Пользователь: «Напомни за 30 и за 10 минут до встречи в 19:00»

```
1. Bash: date → сегодня
2. 18:30 = за 30 минут, 18:50 = за 10 минут
3. ДВА create:
   CHAT="${PRIMARY_CHAT_ID:-$(echo "$ALLOWED_CHAT_ID" | cut -d, -f1)}"
   node dist/schedule-cli.js create "Встреча через 30 минут" "30 18 14 5 *" "$CHAT"
   node dist/schedule-cli.js create "Встреча через 10 минут" "50 18 14 5 *" "$CHAT"
4. Ответ: «Поставил два напоминания: 18:30 и 18:50.»
```

## Просмотр / удаление

- Список: `node dist/schedule-cli.js list`
- Удалить: `node dist/schedule-cli.js delete <ID>`
- Поставить на паузу: `node dist/schedule-cli.js pause <ID>`
- Возобновить: `node dist/schedule-cli.js resume <ID>`

## Если CLI вернул ошибку

- `Invalid cron` → пересчитай (минуты 0-59, часы 0-23, дни 1-31, месяцы 1-12, дни_недели 0-6)
- Любая другая → честно сказать «не получилось поставить, ошибка X». НЕ врать что поставил.

## Запреты

- НЕ передавай `$ALLOWED_CHAT_ID` напрямую если там может быть несколько ID через запятую — `schedule-cli` не парсит список и сохранит строку целиком, scheduler упадёт «chat not found». Всегда через `cut -d,` или `$PRIMARY_CHAT_ID`.
- НЕ говори «напомнил/поставил» без успешного вывода CLI.
- НЕ используй абсолютные пути типа `/opt/claudeclaw/...` — путь зависит от инсталляции.
